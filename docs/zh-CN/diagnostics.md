# 诊断与代码修复

分析器会强制以下规则；`STIA0012` 是唯一的例外，由生成器在代码产出本身失败时报告。大多数规则作为
**编译错误**报告，因此不合法的声明无法通过编译；`STIA0011`、`STIA0013`、`STIA0019` 与 `STIA0024` 是警告，
建议性规则（`STIA0014`、`STIA0015`、`STIA0016`、`STIA0022`）为提示级别。各级别均可按项目在
`.editorconfig` 中调整。诊断文案会按编译器区域设置输出英文或中文。

有几条规则的触发条件比标题看上去更窄：`STIA0011` 要求该 Id 声明了 `Validator` 或 `Normalizer`
（两者都没有时直接构造并不构成绕过），且同时覆盖 `new Xxx(...)`、目标类型化的 `new(...)` 与
`default` / `default(T)`——仅用于比较（`id == default`）时不报告；`STIA0014` **默认关闭**，需显式设置
`dotnet_diagnostic.STIA0014.severity = suggestion` 才会启用；`STIA0016` 对每组共用同一基元的 Id
只报一次，落在组内名字序最小的成员上。

二十六条规则中有十七条提供代码修复，其中几条只在修复方式唯一时才提供 —— `STIA0003` 仅在 Id 自身是泛型时
提供（删掉*包含类型*的类型参数会改变你的设计），`STIA0005` 仅在类型没有显式构造函数时提供（在已有构造函数旁
再加主构造函数会撞 `CS0111`），`STIA0009` 仅在包含类型确实缺 `partial` 时提供（否则会插进第二个 `partial`）。
`STIA0023` 刻意不提供修复：唯一能机械做出的改动是删掉 `Prefix`，而那会改变规范文本形，已经按带前缀格式
写出去的数据将再也读不回来 —— 换一个安全的前缀只能由你来定。两条命名提示（`STIA0015`、`STIA0016`）
同样刻意不提供修复：正确地重命名一个类型意味着同时改掉所有引用，而「这些 Id 看起来一样」本身没有机械修法。
其余九条完全没有修复：`STIA0019` 与 `STIA0024` 报的是声明与编译不匹配——请求了集成却没引用其程序集，
或掩码位不对应任何集成——要靠你补包或改正标志位来解决；`STIA0022` 与前面两条命名提示同属风格建议；
而 `STIA0012`、`STIA0020`、`STIA0021` 出现在任何改写都猜不出意图的地方（`STIA0012` 由生成器而非
分析器上报）。

代码修复通过 IDE 的常规灯泡菜单提供，并支持**在文档 / 项目 / 解决方案中修复全部出现处**。类型可以
拆成多个 `partial` 声明段：类型级规则按整个类型判定一次，参数级规则只在声明主构造函数的那一段上判定，
因此在另一个声明段里追加成员完全合法。
