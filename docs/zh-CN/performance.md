# 性能

采用源码生成器时，有两件事值得关心：它给你的构建增加多少开销，以及生成的代码在运行期有多少开销。
两个答案都很短。

## 运行期

生成的成员就是你手写会写出的代码，没有隐藏成本：

- `Create` 是一次静态调用；配了验证器时再加一次验证器调用。
- `ToString()` 是对基元的一次调用。
- `Parse` 是对基元 `Parse` 的一次调用。
- JSON 转换器是生成的类型，不是基于反射的，因此序列化一个 Id 与序列化它包裹的基元开销相同。

没有反射，也没有装箱——`record struct` 的 Id 是值类型。唯一值得知道的一次分配来自带前缀的 Id：
`ToString()` 要把前缀与取值拼起来，这条路径会分配一个字符串。不设 `Prefix` 就没有额外分配。

## 构建期

生成器只看实现了 `IStronglyTypedId<,>` 的类型，因此它的开销随你声明的 Id 数量增长，而不随引用集的
大小增长。它还会按被引用的程序集缓存查找结果，所以每次按键都重新编译的 IDE 不会反复扫描同一批程序集。

实际上，生成器很少是让构建变慢的原因。如果你怀疑是它，先量一下自己的构建——常见原因是别的分析器，
或者一次冷还原。

## 给维护者

仓库为生成器本身保留了一道按分配量判定的回归门禁。那是 CI 的事，不是使用者需要配置的东西；命令与基线
文件记录在 [CONTRIBUTING](https://github.com/LenFon/StronglyTypedId/blob/main/.github/CONTRIBUTING.md) 里。
